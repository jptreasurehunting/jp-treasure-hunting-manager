# JP Treasure Hunting Manager

## 📋 統合管理・コンプライアンス・利益計算機能 仕様書

本ドキュメントは、**JP Treasure Hunting Manager**（全社統合管理アプリケーション）における利益計算、出品転記、手元実在庫棚卸し、発送適格性、並びに **Zonos Customs Manager**（カスタム申告モジュール）の構造・動態・UIおよびデータ設計仕様を定義します。

---

### 1. 機能概要
商品出品・販売における利益計算の精度向上と柔軟な運用を目的とし、カテゴリー別および商品個別の各種設定（eBay手数料率・関税計算パラメータ）の管理、並びにeBay API（予想手数料・Finances API）との自動比較・同期機能を提供します。

---

### 2. 基本仕様・データ項目

#### 2.1 設定階層構造
1. **カテゴリー別設定（デフォルト設定）**: カテゴリー単位で手数料率・関税パラメータを保持。
2. **商品個別設定（オーバーライド設定）**: 特定商品に個別設定がある場合、カテゴリー設定より優先して適用。

#### 2.2 初期値一覧
| 項目名 | 初期値 | 説明 |
| :--- | :--- | :--- |
| **eBay手数料率** | `20%` (0.20) | カテゴリーごとの基本eBay手数料率 |
| **関税計算用 分母** | `3` | 関税計算式の分母数値 |
| **関税率** | `20%` (0.20) | 輸入・販売に関わる基本関税率 |

---

### 3. 計算ロジック

#### 3.1 関税計算式
関税は以下の計算式に基づいて算出します。

$$ \text{関税額} = \frac{\text{販売価格}}{\text{分母}} \times \text{関税率} $$

- **計算例（初期値の場合）**:
  販売価格が $300 の場合：
  $$ \text{関税額} = 300 \div 3 \times 0.20 = 20 $$

#### 3.2 予想利益計算式
$$ \text{予想利益} = \text{販売価格} - (\text{販売価格} \times \text{eBay手数料率}) - \text{関税額} - \text{仕入価格} - \text{送料・その他経費} $$

---

### 4. 操作・UI仕様（ロック／アンロック機構）

誤操作による不意の設定変更を防ぐため、安全設計を採用します。

1. **固定状態（デフォルト/ロック状態）**
   - 設定画面および商品詳細画面の設定項目は**読み取り専用（Read-only / Disabled）**で表示。
   - 誤入力や誤操作による値の改変を防止。
2. **編集手順（アンロック状態）**
   - 「編集（ロック解除）」ボタンを押下することで、編集モードへ移行。
   - 変更完了後、「保存」ボタンを押下して変更を確定し、自動的に再度ロック状態へ移行。

---

### 5. 商品個別設定仕様

- 各商品ごとにカテゴリー設定とは異なる個別の「手数料率」「関税計算パラメータ（分母・関税率）」を設定可能。
- **適用優先順位**:
  1. 商品個別設定（存在する場合）
  2. カテゴリー別設定（商品個別設定がない場合）

---

### 6. eBay API連携仕様

#### 6.1 予想手数料の自動比較と承認フロー（出品前・出品中）
1. **API取得**: eBay APIから対象商品の最新の予想手数料（Estimated Fees）を取得。
2. **差分チェック**: アプリ内の「現在適用中の設定手数料」と「eBay API予想手数料」を比較。
3. **承認ワークフロー**:
   - 差額が存在する場合、画面上に警告アラートおよび差分プレビューを表示。
   - **利用者が承認（「設定を更新」ボタンを押下）した場合のみ**、新しい手数料設定をシステムに反映・更新。
   - 未承認の場合は既存の固定設定を維持。

#### 6.2 確定利益の再計算フロー（販売後）
1. **Finances API連携**: 商品販売完了後、eBay Finances APIを発行し、実際に発生した最終手数料（Actual Fees）を取得。
2. **確定利益更新**: 実際に徴収された手数料データを元に利益計算を再実行し、「確定利益」として更新・保存。

#### 6.3 APIエラー時のフォールバック処理
- ネットワーク障害やeBay APIのメンテナンス、取得エラー発生時は、**保存済みの固定設定（商品個別設定またはカテゴリー設定）を自動採用**し、利益計算処理を中断させない安全設計。

---

### 7. 履歴管理・適用開始日仕様

設定の透明性と過去データの整合性を担保するため、すべての変更履歴を保持します。

#### 7.1 保存項目
- 設定ID（カテゴリーID / 商品ID）
- 変更前の値（手数料率、分母、関税率）
- 変更後の値（手数料率、分母、関税率）
- 変更実施日時（Timestamp）
- 変更作業者情報
- **適用開始日（Effective Date）**

#### 7.2 過去データへの影響・適用ルール
- 設定変更時に「適用開始日」を指定可能とし、指定日以降の取引・計算に対してのみ新設定を適用。
- 過去の販売済みデータについては、販売時点の手数料・履歴データを保持し、意図しない確定利益の変動を防止。

---

### 8. 日本郵政・Zonos Prepay対応仕様

本セクションでは、配送方法として「日本郵政 海外便」を利用する際のZonos Prepay申告補助機能、eBay APIからの売上データ連携、並びに金銭・外部連携における絶対手動承認原則を定義します。

#### 8.1 配送方法の選択とZonos表示制御
- **選択肢**: 「日本郵政 海外便」 / 「その他（FedEx/DHL等）」
- **動的表示制御**: 「日本郵政 海外便」選択時のみ、Zonos Prepay専用の入力・計算補助セクションを画面上に表示。

#### 8.2 eBay API 売れた商品情報の連携仕様
eBay API（Fulfillment API / Order API）より取得した実際の注文情報を、Zonos Prepay入力補助画面へシームレスに連携します。

- **取得・表示対象項目 (全10項目)**:
  1. **eBay注文番号** (`Order ID` / 例: `14-12345-67890`)
  2. **eBay商品番号** (`Item ID` / 例: `256123456789`)
  3. **商品名** (`Title`)
  4. **商品写真** (`Item Image URL` / プレビュー表示)
  5. **数量** (`Quantity`)
  6. **実際の販売価格** (`Actual Selling Price`)
  7. **通貨** (`Currency` / 例: `USD`)
  8. **配送先国** (`Shipping Country` / 例: `United States`)
  9. **注文日時** (`Order Date` / タイムスタンプ)
  10. **発送状況** (`Fulfillment Status` / 例: `Paid / Ready for Shipment`)

#### 8.3 Zonos Prepay 申告額計算仕様
1. **売れた商品のZonos申告価格候補**
   $$ \text{売れた商品の申告価格候補} = \frac{\text{eBay実際の販売価格}}{3} $$
   - 「日本郵政 海外便」選択時、実際の販売価格の 1/3 を「Zonos申告価格候補」として自動設定します。
   - **確定値にせず**、毎回利用者が内容を確認し、必要に応じて自由に手動変更・調整できる設計とします。

2. **おまけ（ノベルティ等）の複数登録機能**
   - 売れた商品以外に同封する「おまけ」を複数登録可能。
   - 各おまけの入力項目:
     - **おまけの商品名**
     - **数量**
     - **Zonos申告単価**（自動予測は行わず、発送時に利用者がZonos Prepay画面を確認して手入力）
     - **写真**（任意: 画像URL / アップロードプレビュー）
   - **おまけ申告額合計**:
     $$ \text{おまけ申告額合計} = \sum (\text{数量} \times \text{Zonos申告単価}) $$

3. **Zonos申告総額**
   $$ \text{Zonos申告総額} = \text{売れた商品の申告価格候補} + \text{おまけ申告額合計} $$

#### 8.4 コピー・転記補助機能 (Copy-to-Clipboard Helper)
Zonos Prepayの画面 (`https://dashboard.zonosprepay.com/ja/ship`) での手入力を円滑化するため、以下の補助機能を搭載します。

1. **ワンクリックコピー機能**:
   - 注文番号、商品名、申告価格候補、おまけ一覧、申告総額をクリップボードへ一括・または個別にワンクリックでコピー可能。
2. **転記用フォーマット出力**:
   - Zonos画面への貼り付けに適したプレーンテキスト形式での出力表示。

#### 8.5 将来の Zonos API 下書き連携構造および絶対手動承認原則
将来的にZonosの正式なAPI利用権限が取得できた場合を見越し、拡張可能な下書きデータ構造 (`ZonosDraftPayload`) を定義します。

1. **拡張下書きデータ構造 (`ZonosDraftPayload`)**:
   ```json
   {
     "orderId": "14-12345-67890",
     "itemId": "256123456789",
     "destinationCountry": "US",
     "productDeclaredValue": 100.00,
     "bonusItems": [
       { "name": "KeyChain", "quantity": 1, "declaredUnitPrice": 3.00, "imageUrl": "..." }
     ],
     "totalDeclaredValue": 103.00
   }
   ```

2. **絶対手動承認原則 (完全非自動化)**
   - 現段階および将来のAPI連携時を問わず、以下の処理に対する**自動実行は一切行いません**。
     - Zonosへの申告価格の確定
     - Zonosへのデータ自動送信 / 自動入力
     - Zonosへの自動支払い
     - eBay上の価格変更および書き込み処理
   - **承認フローの義務付け**:
     - 必ず利用者が毎回、申告価格（販売価格の1/3自動計算候補額を含む）とおまけを含む全商品情報を発送時に確認・修正。
     - 二段階確認画面（モーダル）にて `[ ] 申告価格を確認しました` のチェックをオンにし、明示的に「実行する」ボタンを押下した場合にのみ、承認されたアクションを実行します。
     - 利用者が確認・承認するまで、**Zonosへの送信・申告価格の確定・支払い**は絶対に実行されません。

#### 8.6 最終確認画面（二段階承認モーダル）UI仕様
利用者が実行ボタンを押した場合でも、必ず以下の項目を網羅した**最終確認画面**を表示します。

- **必須表示項目 (全7項目)**:
  1. **売れた商品の一覧**（商品名・数量・写真）
  2. **販売価格**（eBay実際の販売価格）
  3. **1/3申告価格候補**（自動算出および手動修正後の申告額）
  4. **おまけ一覧**（おまけ商品名・数量・申告単価・小計）
  5. **Zonos申告総額**（商品申告額 ＋ おまけ申告額合計）
  6. **発送方法**（例: 日本郵政 海外便）
  7. **配送先国**（例: United States）

- **誤操作防止チェック機構**:
  - 利用者が **`[ ] 確認しました`** にチェックを入れ、かつ **「実行する」** ボタンを押さない限り、外部サイトへの送信・支払い・API実行は絶対に行いません。
  - 「実行する」ボタンは初期状態で**非活性 (Disabled)**とし、チェックボックス選択によってのみ有効化します。
